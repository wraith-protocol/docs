A sender can generate a one-time Stellar address using just the recipient's **public** spending and viewing keys. The recipient uses their private viewing key to recognize the payment. Try both roles locally before connecting your application to a network.

## Run the example

Clone the [docs repository](https://github.com/wraith-protocol/docs/tree/develop/scripts/rust-quickstart) and use a recent stable Rust toolchain. Start in the repository root:

```bash
cd scripts/rust-quickstart
cargo test --locked
```

The tests inject public, deterministic fixtures from the pinned TypeScript SDK. They need no wallet, funds, or RPC endpoint. To run the binary, provide a **disposable** Stellar seed through the `STELLAR_SECRET` environment variable using your local secret manager, then run `cargo run --locked` from the same directory. It prints only the public one-time address. Never use the published test seeds for funds.

## Derive keys and generate an address

Here is the entire [example program](https://github.com/wraith-protocol/docs/blob/develop/scripts/rust-quickstart/src/main.rs). Its Cargo dependencies and lockfile are in the same crate.

```rust
use anyhow::{Context, Result};
use ed25519_dalek::SigningKey;
use stellar_strkey::ed25519::PrivateKey;
use wraith_rust_quickstart::{generate, Recipient};

fn main() -> Result<()> {
    let seed: PrivateKey = std::env::var("STELLAR_SECRET")
        .map_err(|_| anyhow::anyhow!("provide a disposable test seed through STELLAR_SECRET"))?
        .parse()
        .context("invalid Stellar secret seed")?;
    let recipient = Recipient::derive(&SigningKey::from_bytes(&seed.0));
    let (spending, viewing) = recipient.public_keys();
    let announcement = generate(&spending, &viewing)?;
    anyhow::ensure!(recipient.matches(&announcement)?, "address did not match");
    println!("Matched one announcement for {}", announcement.address);
    Ok(())
}
```

`Recipient::derive` signs the SDK's fixed Stellar key-derivation message. Treat that signature as key material: anyone with it can derive both keys. Keep the signature and signing keys out of logs.

`generate` takes only the public keys. For each payment it creates a fresh ephemeral Ed25519 key using the operating system RNG. It converts the recipient's viewing key to Montgomery form for X25519 key agreement, hashes the shared secret to a scalar, and adds that scalar's public point to the public spending key. The resulting Stellar account address belongs to the recipient.

## Scan announcements

On your chosen network, query the [announcer contract](/reference/contract-registry) with Stellar RPC `getEvents`. Filter for successful contract events from that contract with the `announce` symbol and scheme ID `2`. Resume from the RPC pagination cursor between pages. For network URLs and passphrases see [Stellar networks](/reference/stellar-networks).

For each matching v2 event, pass its base64 XDR `value` to `Announcement::from_event_value`. The value is a tuple of the destination account, ephemeral public key, and metadata. The first metadata byte is the view tag. Pass the decoded announcement to `recipient.matches`: it checks the tag, then reconstructs the full destination address using the private viewing key. A tag match alone does not identify a payment.

The [executable scanner test](https://github.com/wraith-protocol/docs/blob/develop/scripts/rust-quickstart/src/tests.rs) decodes five recorded RPC values. Two belong to the recipient. A third has a matching tag but a different address.

## Prepare a send

`Announcement::send_call` builds an unsigned `InvokeContractArgs` for [stealth-sender.send](/contracts/stellar#stealth-sender). Supply the deployed sender contract ID, the caller's Stellar address, the token contract ID, and a positive amount in the token's smallest units. The helper fills in the one-time destination, scheme ID, ephemeral public key, and view-tag metadata.

The [fixture](https://github.com/wraith-protocol/docs/blob/develop/scripts/rust-quickstart/src/lib.rs) stops at the XDR boundary. To submit on a network, wrap the invocation in a transaction for the correct network passphrase and source account, simulate it, inspect the result and authorization entries, then sign and submit through your wallet or relayer. See [Stellar crypto primitives](/sdk/chains/stellar) for the corresponding TypeScript SDK operations.
